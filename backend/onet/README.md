# O*NET source

Prepares [O*NET](https://www.onetcenter.org/) (the US Department of Labor's
occupation database) as an incoming source for the taxonomy pipeline's
classification rounds. Its Software Skills file is already one row per
occupation-software link, so `taxonomy-pipeline import-source` reads it
directly with `onet_mapping.yaml`; there is no flatten script (see "Next
round" in `../taxonomy_pipeline/README.md`).

## Layout

```text
onet/
├── raw/                     # the downloaded O*NET file (gitignored, see below)
├── onet_mapping.yaml        # import-source mapping: which column is category / speciality / tag
├── soc_major_groups.csv     # SOC 2018 major-group labels, for the category derived from the code
├── onet_taxonomy.sql        # generated by import-source: onet_categories / _specialities / _tags / _speciality_tags
└── onet_tag_context.json    # generated by import-source: each tag's commodity title, for Case B
```

## Getting the data

On onetcenter.org, download **Software Skills** in Excel format (no sign-up
needed) and save it as `raw/Software Skills.xlsx`. Its header row is
`O*NET-SOC Code, Title, Workplace Example, Element ID, Element Name, Hot
Technology, In Demand`. The full database zip's `Technology Skills.xlsx` holds
the same data with `Example` / `Commodity Title` instead of `Workplace Example`
/ `Element Name`; point `onet_mapping.yaml` at whichever you have. O*NET is published under a CC BY 4.0
licence; credit "O*NET" if you redistribute derived data.

## Mapping onto the taxonomy

| Taxonomy level | O*NET | Example |
|---|---|---|
| service | fixed: Function (id 2), set in `onet_mapping.yaml` | Function |
| category | SOC major group: the code's first 2 digits, named from `soc_major_groups.csv` | Computer and Mathematical |
| speciality | occupation (`Title`) | Data Scientists |
| tag | software (`Workplace Example`) | Python |
| tag description | software type (`Element Name`) | Object or component oriented development software |

`onet_mapping.yaml` keeps only `Hot Technology = Y` rows at first: 22
categories, 904 occupations, 176 software and 11,571 links (release downloaded
2026-10-31). Delete its `filters` block for everything: 923 occupations, 8,753
software and 31,821 links, so roughly 50 times the judge and Case B cost.

## Running it

From `backend/taxonomy_pipeline/`, with the pipeline installed (`../.venv`):

```bash
taxonomy-pipeline import-source --mapping ../onet/onet_mapping.yaml \
    --baseline-snapshot integrations/judged-1015   # previous round's snapshot
```

It writes `onet_taxonomy.sql`, `onet_tag_context.json` and the round config
(`configs/judged-1015_vs_onet.yaml`), and prints the round's `run`, `case-a`
and `case-b` commands. If a column name differs in a later O*NET release, it
stops and lists the headers the file has; fix the names in `onet_mapping.yaml`.
A warning about an unlabelled code prefix means `soc_major_groups.csv` is
missing a group.
